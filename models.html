// MODELS ◈ THE GRIMM SERIES

Specialists,
trained in threes.

三進モデル · ポケットに入る頭脳

The Grimm Series is our model family, and each name in it is a class, not a single model. A class is a size and a home: how big the model is, and where it runs. Inside each class live specialists, models trained for one field each, so a small model can be genuinely good at its job instead of mediocre at everything.

Specialists are fields, not features: the core subjects that push a field forward, math, physics, history, religion, plus the computing disciplines. Every specialist is trained at every class scale: the same mind, from your phone to your workstation. All of them are open mixture-of-experts (MoE) models with three-value weights {−1, 0, +1}, the specialists are the experts, and the model routes each job to the mind trained for it.

⬢ STATUS // In development. No Grimm model is released or downloadable yet, the first proof of concept is being trained now (below).

EFFICIENT BY DESIGN効率設計

Every weight, the numbers a model is made of, is stored as −1, 0 or +1 instead of a long decimal. About 1.6 bits per weight instead of 16: roughly a tenth of the memory, with multiplication swapped for simple addition. MoE routing means each question wakes only the experts it needs, not the whole library. Our edge is the tuning data and the judging harness, not the weights. Those ship open.

WHY TERNARYなぜ三進法か

−1 / 0 / +1 Three digits instead of two. Flipping a sign just flips digits; cutting off digits is the same as rounding. Donald Knuth called balanced ternary "the prettiest number system of all" (The Art of Computer Programming, Vol. 2, §4.1).
BASE 3 ≈ e Three symbols per digit is mathematically the most efficient whole-number way to represent information. That's an information-theory result, real hardware costs are messier. We know the difference.
≈1.6 BITS Modern proof it works: ternary-weight models (like BitNet b1.58) store each weight in about 1.6 bits instead of 16, roughly a tenth of the memory, and swap multiplication for add/subtract. That's the real mechanism. The zeros buy accuracy that two-value compression can't.
THE GOAL Specialists that answer like much larger models but live on hardware you own, offline, private, no subscription. That's the goal, not a promise: each specialist ships only after its numbers are measured on real hardware and published.

⬢ STRAIGHT TALK // This is ternary weight compression running on standard hardware, less memory traffic, no multiplication, not ternary circuits. We say so because we'd want to be told.

Measured, never estimated Benchmarks and model-fit scores are published only after we measure them on real hardware, ours, or a contributor's, with the device named. If a number isn't measured, it isn't on the page. ◈ STANDING PROMISE
